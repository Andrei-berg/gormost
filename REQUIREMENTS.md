# REQUIREMENTS.md — Gormost: Требования к системе

> Документ фиксирует что система делает (v1), что войдёт в v2,
> и что намеренно вынесено за рамки проекта.

---

## Контекст

**Кто использует:** сотрудники ГБУ «Горьмост», Лефортовский тоннель.
**Зачем:** заменить бумажные наряды и WhatsApp-переписку — всё в одном интерфейсе.
**Как используется:** на рабочих компьютерах в диспетчерской и на телефонах у мастеров/бригадиров.
**Критичность:** система для внутренней работы, не для внешних пользователей. Простой на несколько часов допустим.

## v1 — Что реализовано сейчас

### Авторизация
- Вход по табельному номеру + 4-значный PIN
- Ролевая модель: 9 ролей (ADMIN, BOSS, ZAMPORAB, HEAD, DISPATCHER, FOREMAN, TRANSPORT, COMPLAINTS, WORKER)
- Каждая панель доступна только разрешённым ролям
- Сессия хранится в localStorage браузера
- Ручное завершение сессии (кнопка «Выйти»)

### Заявки (основная сущность)
- Создание заявки: служба, категория, объект, конструкция, вид работы, описание, дата, смена
- Поля приоритета: LOW / MEDIUM / HIGH / CRITICAL
- Поля срочности: NORMAL / URGENT / EMERGENCY
- Статусы: NEW → PLANNED → IN_PROGRESS → CHECKING → DONE
- Цепочка согласования:
  - Начальник службы → `approved_by_head`
  - Зам/Прораб → `approved_by_zamporab` (переводит в PLANNED)
  - Босс → `approved_by_boss` (опциональное финальное согласование)
- Назначение исполнителей: один или несколько сотрудников на заявку
- Фиксация времени: `fact_start` при переходе в IN_PROGRESS, `fact_finish` при DONE
- Назначение транспорта: поле `transport_type` на заявке

### Панели (8 штук)
- **Диспетчер** — канбан + таблица, KPI, статистика людей, автообновление 30с
- **Зам/Прораб** — согласование заявок, таймер до 16:30, запросы людей между службами
- **Мастер/Бригадир** — мои задачи, смена статуса, фильтр «мои / все»
- **Начальник службы** — заявки своей службы, назначение людей, согласование
- **Босс** — KPI-дашборд, health-индикатор (🟢🟡🔴), графики, лог
- **Транспорт** — автопарк (5 единиц), назначение техники на заявки
- **Жалобы** — регистрация обращений, приоритет, статус обработки
- **Админ** — CRUD справочников: пользователи, службы, категории, объекты, конструкции, виды работ, лог

### Справочники
- Иерархия: Категория → Объект → Конструкция → Вид работы
- 5 служб: SRV-ENG, SRV-STR, SRV-FIRE, SRV-VENT, SRV-CCTV
- Управление пользователями: роль, служба, PIN, активность

### Система смен
- Автоматическое определение текущей смены по дате
- 4 начальника смен, цикл 1/3 (работа/отдых)
- Период: день (07:00–19:00) / ночь (19:00–07:00)

### Аудит
- Все действия (создание, изменение, согласование, логин) пишутся в `changelog`
- Лог доступен в Босс-панели и Админ-панели (только чтение)

## v2 — Что планируется

### HR-модуль (высокий приоритет)

**Актуальность состава — основная задача панели:**
- Отображение текущего статуса каждого сотрудника: на работе / отгул / больничный / отпуск / уволен
- Быстрое изменение статуса с указанием причины и дат
- История изменений статуса по каждому сотруднику
- Сводка по службам: сколько людей сегодня работает / отсутствует

**Отчёты:**
- Сводка на текущий день: присутствие по службам
- Табель за период (сетка сотрудник × день)
- Отчёт по отпускам и больничным за месяц/квартал
- Экспорт в Excel или печать

**Карточка сотрудника:**
- Контакты, должность, служба, роль в системе
- Текущий статус с датой начала
- История назначений на заявки
- Приём / увольнение (soft-delete с датой)

**Доступ:** ADMIN, BOSS, ZAMPORAB (возможно — отдельная роль HR, обсудить)

**Новые таблицы в БД:**
- `employee_status` — история статусов (user_id, status, date_from, date_to, reason)
- Поля в `users`: date_hired, date_fired

### Печать нарядов (ожидаем шаблоны)
- HTML-шаблон наряда по форме ГБУ
- Кнопка «Печать» на заявке → `window.print()` или PDF
- Сводный наряд по смене

### Доработка UI/UX (v1.1)
- Настройки вынести из основной навигации
- Навигация показывает только доступные роли панели
- Пустые состояния с понятным текстом
- Базовая адаптация под мобильные экраны

### Realtime (v2.1)
- Заменить polling на Supabase Realtime subscriptions
- Данные обновляются мгновенно без кнопки «Обновить»

### Экспорт (v2.2)
- Выгрузка заявок в Excel (по дате / смене / службе)
- Отчёт по смене для передачи дежурства

## За рамками проекта (не делаем)

| Что | Почему |
|-----|--------|
| Мобильное приложение (iOS/Android) | Веб-версия достаточна, PWA рассмотрим позже |
| Интеграция с внешними системами (1С, SAP) | Нет требования от заказчика |
| Email/SMS-уведомления | Нет инфраструктуры, не запрошено |
| Многоязычность | Только русский язык |
| Офлайн-режим | Supabase требует подключения |
| Видеонаблюдение / IoT | За рамками веб-приложения |
| Финансовый учёт / зарплата | Отдельная система |
| Автоматические тесты | Пока не приоритет |
| Поддержка IE / старых браузеров | Только современные Chrome/Edge/Firefox |

## Нефункциональные требования

### Доступность
- Работает в браузере на рабочих ПК (Windows + ALT Linux)
- Базовая читаемость на телефоне (мастера/бригадиры)

### Производительность
- Страница загружается за < 3с при нормальном соединении
- Канбан-доска отзывается мгновенно (drag-and-drop)
- Таблица до ~500 заявок без пагинации

### Надёжность
- Простой до нескольких часов допустим (не 24/7 критично)
- Все изменения логируются в changelog
- Нет потери данных при обновлении страницы

### Безопасность
- PIN хранится в БД (не хэшируется — внутренняя система)
- Роли проверяются на клиенте (AuthGuard) — достаточно для внутреннего использования
- Supabase credentials только в env-переменных, никогда в коде

### Сопровождаемость
- Любой модуль можно удалить/добавить без переписывания остального кода
- Новый разработчик понимает структуру за 30 минут (CLAUDE.md + ARCHITECTURE.md)
- `npm run build` = минимальная проверка качества перед коммитом

## Ограничения и допущения

- **БД:** Supabase (PostgreSQL). Миграции выполняются вручную через SQL Editor.
- **Деплой:** Vercel. Push в `main` = автодеплой. Ветка `main` всегда в рабочем состоянии.
- **Пользователей:** < 100. Нет нагрузочных требований.
- **Данных:** < 10 000 заявок в обозримом будущем.
- **Команда:** 1 разработчик + AI-агент. Архитектура это учитывает.
