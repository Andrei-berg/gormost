## Integration Checker Results

**Overall status: PARTIAL** — Core Phase 02→03→04 chain is wired but 2 critical cross-phase bugs found.

### INT-01 — SummaryPanel ABSENT_STATUSES Incomplete (Critical)

**Affects:** HR-05, HR-16
**From:** Phase 04 `EmployeeCard.tsx` EXTENDED_STATUSES (6 new statuses)
**To:** Phase 03 `SummaryPanel.tsx` line 6

`SummaryPanel.tsx` defines:
```ts
const ABSENT_STATUSES = ['Otgul', 'Bolnichniy', 'Otpusk', 'Uvolen']
```

Phase 04 added 6 new statuses to `EmployeeStatusType` and `EMPLOYEE_STATUS_CONFIG`, but `ABSENT_STATUSES` was not updated. Employees set to `Komandirovka`, `Uchebniy_otpusk`, `Dekret`, `Mobilizovan`, `SVO`, or `Troydoustroyen_s_SVO` are displayed as "working" in the SummaryPanel tiles.

**Fix:** Add all 6 extended statuses to `ABSENT_STATUSES`, or derive the array from `EMPLOYEE_STATUS_CONFIG` using a flag field.

### INT-02 — service_id Never Set on Hired/Seeded Employees (Critical)

**Affects:** HR-08, HR-18
**From:** `HireModal.tsx` + `007_seed_employees.sql`
**To:** `src/app/hr/page.tsx` line 42

`page.tsx` filters employees via:
```ts
employees.filter(e => e.user.service_id !== null)
```

Two problems:
1. `HireModal.tsx` calls `createEmployee()` with `service_id: null` (hardcoded)
2. `007_seed_employees.sql` INSERT column list omits `service_id` — all 270 seeded employees have `service_id = NULL`

Result: All 270 seeded employees and any employee hired via HireModal are **silently hidden** from the `/hr` page. The page renders an empty list for ZAMPORAB/ADMIN.

**Fix:**
- `HireModal.tsx`: Add a service dropdown populated from `fetchServices()` — required field
- `007_seed_employees.sql` or a follow-up migration `008`: SET `service_id` for all seeded employees based on their section/group data

### INT-03 — resolveShiftForDate() Has Zero Callers (Informational)

**Affects:** HR-17
**Status:** Expected — designed for Phase 05

`resolveShiftForDate()` in `src/lib/shifts.ts` is fully implemented and correct for all 6 schedule types. It has no callers in the current codebase. This is intentional — the function will be consumed by the Phase 05 attendance grid. No action needed now.
