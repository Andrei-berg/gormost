# REQUIREMENTS.md — Gormost: Требования к системе

> Документ фиксирует что система делает (v1), что войдёт в v2,
> и что намеренно вынесено за рамки проекта.

---

## Контекст

**Кто использует:** сотрудники ГБУ «Горьмост», Лефортовский тоннель.
**Зачем:** заменить бумажные наряды и WhatsApp-переписку — всё в одном интерфейсе.
**Как используется:** на рабочих компьютерах в диспетчерской и на телефонах у мастеров/бригадиров.
**Критичность:** система для внутренней работы, не для внешних пользователей. Простой на несколько часов допустим.

---

## v1 — Реализовано (MUST)

### Авторизация
- **REQ-001** Вход по табельному номеру + 4-значный PIN
- **REQ-002** Ролевая модель: 9 ролей (ADMIN, BOSS, ZAMPORAB, HEAD, DISPATCHER, FOREMAN, TRANSPORT, COMPLAINTS, WORKER)
- **REQ-003** Каждая панель доступна только разрешённым ролям (AuthGuard)
- **REQ-004** Сессия хранится в localStorage браузера
- **REQ-005** Ручное завершение сессии (кнопка «Выйти»)

### Заявки (основная сущность)
- **REQ-010** Создание заявки: служба, категория, объект, конструкция, вид работы, описание, дата, смена
- **REQ-011** Приоритеты: LOW / MEDIUM / HIGH / CRITICAL
- **REQ-012** Срочность: NORMAL / URGENT / EMERGENCY
- **REQ-013** Статусы: NEW → PLANNED → IN_PROGRESS → CHECKING → DONE
- **REQ-014** Цепочка согласования: HEAD → ZAMPORAB → (опционально BOSS)
- **REQ-015** Назначение исполнителей: один или несколько сотрудников на заявку
- **REQ-016** Фиксация времени: fact_start при IN_PROGRESS, fact_finish при DONE
- **REQ-017** Назначение транспорта: поле transport_type на заявке

### Панели (8 штук)
- **REQ-020** Диспетчер — канбан + таблица, KPI, статистика людей, автообновление 30с
- **REQ-021** Зам/Прораб — согласование заявок, таймер до 16:30, запросы людей между службами
- **REQ-022** Мастер/Бригадир — мои задачи, смена статуса, фильтр «мои / все»
- **REQ-023** Начальник службы — заявки своей службы, назначение людей, согласование
- **REQ-024** Босс — KPI-дашборд, health-индикатор (🟢🟡🔴), графики, лог
- **REQ-025** Транспорт — автопарк (5 единиц), назначение техники на заявки
- **REQ-026** Жалобы — регистрация обращений, приоритет, статус обработки
- **REQ-027** Админ — CRUD справочников: пользователи, службы, категории, объекты, конструкции, виды работ, лог

### Справочники
- **REQ-030** Иерархия: Категория → Объект → Конструкция → Вид работы
- **REQ-031** 5 служб: SRV-ENG, SRV-STR, SRV-FIRE, SRV-VENT, SRV-CCTV
- **REQ-032** Управление пользователями: роль, служба, PIN, активность

### Система смен
- **REQ-040** Автоматическое определение текущей смены по дате
- **REQ-041** 4 начальника смен, цикл 1/3 (работа/отдых)
- **REQ-042** Период: день (07:00–19:00) / ночь (19:00–07:00)

### Аудит
- **REQ-050** Все действия (создание, изменение, согласование, логин) пишутся в `changelog`
- **REQ-051** Лог доступен в Босс-панели и Админ-панели (только чтение)

## За рамками проекта (не делаем)

| Что | Почему |
|-----|--------|
| Мобильное приложение (iOS/Android) | Веб-версия достаточна, PWA рассмотрим позже |
| Интеграция с внешними системами (1С, SAP) | Нет требования от заказчика |
| Email/SMS-уведомления | Нет инфраструктуры, не запрошено |
| Многоязычность | Только русский язык |
| Офлайн-режим | Supabase требует подключения |
| Видеонаблюдение / IoT | За рамками веб-приложения |
| Финансовый учёт / зарплата | Отдельная система |
| Автоматические тесты | Пока не приоритет |
| Поддержка IE / старых браузеров | Только современные Chrome/Edge/Firefox |

## Нефункциональные требования

### Доступность
- Работает в браузере на рабочих ПК (Windows + ALT Linux)
- Базовая читаемость на телефоне (мастера/бригадиры)

### Производительность
- Страница загружается за < 3с при нормальном соединении
- Канбан-доска отзывается мгновенно (drag-and-drop)
- Таблица до ~500 заявок без пагинации

### Надёжность
- Простой до нескольких часов допустим (не 24/7 критично)
- Все изменения логируются в changelog
- Нет потери данных при обновлении страницы

### Безопасность
- PIN хранится в БД (не хэшируется — внутренняя система)
- Роли проверяются на клиенте (AuthGuard) — достаточно для внутреннего использования
- Supabase credentials только в env-переменных, никогда в коде

### Сопровождаемость
- Любой модуль можно удалить/добавить без переписывания остального кода
- Новый разработчик понимает структуру за 30 минут (CLAUDE.md + ARCHITECTURE.md)
- `npm run build` = минимальная проверка качества перед коммитом

## Ограничения и допущения

- **БД:** Supabase (PostgreSQL). Миграции выполняются вручную через SQL Editor.
- **Деплой:** Vercel. Push в `main` = автодеплой. Ветка `main` всегда в рабочем состоянии.
- **Пользователей:** < 100. Нет нагрузочных требований.
- **Данных:** < 10 000 заявок в обозримом будущем.
- **Команда:** 1 разработчик + AI-агент. Архитектура это учитывает.
