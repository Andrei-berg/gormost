# Requirements: Gormost — v3.0 «Планировщик-агент»

**Defined:** 2026-09-01
**Core Value:** Диспетчер/мастер наговаривает или вставляет текст работ — агент, обученный словарю участка, раскладывает его в черновики плана день/ночь по службам; человек проверяет и публикует.

Research: `.planning/research/SUMMARY.md` (+ STACK / FEATURES / ARCHITECTURE / PITFALLS).

Guiding principle — **resolve, don't generate:** LLM только сегментирует текст; детерминированный резолвер сопоставляет каждое поле с реальным ID каталога или `null`; ограждения живут над провайдер-адаптером; единственная точка записи — неопубликованные `daily_plan_items` за явным кликом человека.

## v3.0 Requirements

### KB — База знаний (каталог + алиасы)

- [x] **KB-01**: Система создаёт таблицу `entity_aliases` (`surface` нормализованный, `canonical_type` object|construction|work_type|service, `canonical_id`, `scope_object_id?`, `weight`, `source` seed|manual|voice|correction, `created_by`) с политикой `anon_all_entity_aliases`
- [ ] **KB-02**: Система добавляет к `work_types` атрибуты для агента — `service_id` (чья служба), `unit` (ед.изм.), `typical_period` (день/ночь/сутки), `typical_crew` (jsonb: рабочие/мастера/ИТР/техника); редактируются в `/admin` → «Виды работ»
- [ ] **KB-03**: ADMIN ведёт алиасы (CRUD): поиск, показ `source`, предупреждение о коллизии «одна фраза → два разных каноника»
- [x] **KB-04**: Резолвер сопоставляет фразу с сущностью каталога по точному алиасу + нечёткому совпадению через общий пайплайн русской нормализации/лемматизации (ё→е, `№`, сокращения, падежи), применяемый одинаково к каталогу, алиасам, диктовке и ячейкам Excel; нет совпадения выше порога → поле 🔴, остаётся свободным текстом, сущность НЕ выдумывается
- [ ] **KB-05**: Охват каталога — только участок Гормост-Лефортово (транспортные тоннели ЛТР + Шереметьевский/Митьковский/Нижегородский, пешеходные тоннели ТТК участка, ЗБ ЛТР/ГТР, мосты участка); связь базы знаний с журнальным каталогом (`journal_objects`), а не отдельный четвёртый остров сущностей

### IMP — Инструмент обучения (импорт из Excel)

- [ ] **IMP-01**: ADMIN загружает .xls/.xlsx (Титул уборки / Конструктив / Годовой план 2026) через Supabase Storage по signed URL; функция читает файл на сервере (не через тело запроса — лимит 4.5 МБ)
- [ ] **IMP-02**: Импорт распознаёт тип листа и применяет преднастроенное сопоставление колонок для трёх известных форм; при дрейфе заголовков — явная ошибка, никогда не хардкод индекса колонки
- [ ] **IMP-03**: Строки попадают в staging (`catalog_import_batches` / `catalog_import_rows`, RLS `anon_all_*`) и классифицируются по уровню каталога (объект / конструктив / вид работ / алиас)
- [ ] **IMP-04**: ADMIN видит предпросмотр-диф (новое / изменённое / дубль), отмечает галочками строки и подтверждает в каталог только выбранное
- [ ] **IMP-05**: Импорт устойчив к грязным файлам: forward-fill объединённых заголовков-секций, дедуп по нормализованному+лемматизированному ключу, «conflicted copy» / «(копия)» не создают двойной каталог, инв.№ не считается надёжным ключом
- [ ] **IMP-06**: Каждая строка staging помнит файл-источник и номер строки (провенанс)

### AI — Провайдер-независимый слой + ограждения

- [ ] **AI-01**: Два внутренних интерфейса — `extractPlan(text) → PlanRow[]` и `transcribe(audio) → text`; по адаптеру на бэкенд; провайдер и модель выбираются через env/конфиг без изменения кода; новые env-переменные, существующие не переименовываются
- [ ] **AI-02**: Минимум один рабочий LLM-адаптер и один STT-адаптер + mock-адаптер для офлайн-тестов и eval
- [ ] **AI-03**: Structured output — промпт-инструктированный JSON + Zod `safeParse` + один repair-retry, одинаково для всех провайдеров (без `generateObject` / провайдерного constrained decoding)
- [ ] **AI-04**: LLM/STT/аудио/xls вызовы идут через отдельные роуты `/api/agent/*` (Node runtime, свой `maxDuration`), не через `/api/db`; ключи только на сервере
- [ ] **AI-05**: Слой ограждений над адаптером, не зависящий от провайдера: whitelist сущностей из каталога, два порога уверенности в конфиге, кап числа строк, `max_tokens` и размера входа, таймаут → fallback на ручной модал; граница защиты от prompt-injection (вывод по схеме не может нести команду «создать заявку»)
- [ ] **AI-06**: Неизменяемый лог разборов (`plan_parse_sessions` / `plan_parse_corrections`): provider, model, версия промпта, токены, стоимость; RLS `anon_all_*`
- [ ] **AI-07**: Роуты агента гейтятся по ролям (`ROLE_RESTRICTED`) + ограничение частоты вызовов на пользователя (публичный демо-URL с общим PIN)
- [ ] **AI-08**: eval-харнесс (`npm run eval`, отдельно от `npm run test`, офлайн против mock-адаптера): пофразовая precision/recall экстракции, стартовый золотой набор ~30 реальных диктовок; release-gate, не per-commit

### EXT — Экстракция (текст → строки)

- [ ] **EXT-01**: Вставленный текст → N строк `{объект, служба, работа, период, рабочие, мастера, ИТР, техника, исходная фраза, уверенность по полям}`
- [ ] **EXT-02**: Одна диктовка на несколько служб автоматически группируется по резолвнутой службе; человек переопределяет группировку в предпросмотре
- [ ] **EXT-03**: Одна фраза с несколькими работами/объектами разбивается на несколько строк (чистая тестируемая функция)
- [ ] **EXT-04**: Каждое поле получает чип 🟢 resolved / 🟡 fuzzy (с ранжированным списком кандидатов) / 🔴 unresolved; числовой скор — в тултипе; resolution-confidence (от силы совпадения) отделена от слабой self-confidence модели; строки сортируются худшими вверх
- [ ] **EXT-05**: Агент предзаполняет период и состав из атрибутов вида работ (`typical_period`, `typical_crew`); человек правит

### REV — Предпросмотр и черновики

- [ ] **REV-01**: Редактируемый предпросмотр использует те же виджеты, что ручной модал «Новая запись плана» (комбобокс объекта с созданием на лету, выбор службы, переключатель периода, счётчики состава) — вынесенные в общие компоненты
- [ ] **REV-02**: По строке — принять / отклонить; массово принять все 🟢; split (строка → две); merge (две → одна); сменить службу строки; выбрать из ранжированных кандидатов для 🟡
- [ ] **REV-03**: «Исходная фраза» всегда показана рядом со строкой; строка с нерезолвнутым обязательным полем не может быть закоммичена
- [ ] **REV-04**: «Создать черновики» пишет принятые строки в `daily_plan_items` как неопубликованные на выбранную дату + смену; агент никогда не публикует и не трогает `requests` / `work_plans` / статусы / наряд-допуск / пофамильный состав — инвариант проверяется тестом на запрещённый импорт
- [ ] **REV-05**: Точки входа — кнопка «🎤 Надиктовать план» в `/journal` (BOSS/ADMIN) и `/dispatcher` (DISPATCHER/BOSS/ADMIN), гейт через `ROLE_RESTRICTED`

### VOICE — Голосовой ввод

- [ ] **VOICE-01**: Запись в браузере (MediaRecorder, `audio/webm;codecs=opus`, без библиотеки и транскода) → загрузка в приватный бакет Storage по signed URL → `transcribe()`
- [ ] **VOICE-02**: Расшифровка показывается и редактируется до запуска экстракции; дальше — тот же текстовый пайплайн
- [ ] **VOICE-03**: Аудио удаляется после успешной расшифровки; транскрипция — асинхронной задачей, не удержанием HTTP-запроса

### LOOP — Обучение на исправлениях

- [ ] **LOOP-01**: Каждая правка в предпросмотре, меняющая резолв сущности, логируется (`raw_phrase`, поле, значение модели, уверенность модели, значение человека, действие)
- [ ] **LOOP-02**: «Запомнить исправление» — при 🔴→выбрано / 🔴→создать-новое правка сохраняется в `entity_aliases` (`source='correction'`) и сразу влияет на следующий разбор; при исправлении неверного 🟢/🟡 — спрашивать, чтобы разовая опечатка не засоряла базу

### Testing

- [ ] **TST-01**: Тесты (Vitest, только чистая логика): резолв/скоринг алиасов и нечёткого совпадения, русская нормализация/лемматизация, multi-item split, маппинг строки → `daily_plan_item`, классификация строк Excel, forbidden-import guard для REV-04. Не покрываются: сами LLM/STT вызовы.

## Future Requirements (v3.x / later)

- Очередь разборов с низкой уверенностью + курирование в один клик (создать алиас / создать запись каталога / отклонить) — когда накопится объём исправлений
- Детект конфликтов при импорте (инв.№ / имя+родитель против живого каталога)
- Инлайн «создать запись каталога» прямо из предпросмотра плана (флаг `provisional` → очередь)
- Второй LLM/STT-адаптер (YandexGPT + SpeechKit рядом с дефолтным) — доказать абстракцию
- Scope-aware алиасы (одно сокращение — разное по тоннелям ЛТР/ГТР/ТТК/ЗБ)
- История сессий разбора / undo-redo
- Голосовое добавление сущностей в инструмент обучения (нужна командная грамматика)
- Few-shot самоулучшение из курируемых исправлений
- Дашборд здоровья базы знаний (виды работ без службы, объекты без алиасов, самые исправляемые фразы)
- Автоподстройка порогов уверенности по истории исправлений
- Автокалибровка / продакшн-мониторинг дрейфа качества экстракции, дашборд стоимости, kill-switch по бюджету

## Out of Scope

| Feature | Reason |
|---------|--------|
| Годовой план-график (помесячный контроль выполнения из Годового плана) | Отдельный домен планирования; Годовой план — только источник словаря видов работ (`typical_period`), остальное игнорируется |
| Материалы и нормы расхода | Складской домен; нет потребителя в суточном плане |
| Агент создаёт заявки (`requests`) или план-наряды (`work_plans`) | Обходит цепочку согласования; журнал намеренно не воронка в `work_plans` |
| Объёмы / нормо-часы / расчёт трудозатрат | Оценочный движок; вне задачи диктовки |
| Полный реестр из 59 разделов (фонтаны, памятники, набережные, Кремль) | На порядок больше данных; в суточном плане тоннельного участка не встречается |
| Автопубликация черновиков | Убирает человеческий гейт, на котором держится весь дизайн |
| Дообучение / тренировка своей NER-модели | Не нужно при таком размере каталога; «обучение» = рост `entity_aliases` + опциональный few-shot |
| Агент назначает рабочих пофамильно | Формирование бригад — авторская работа мастера (`work_assignments`) |
| Чат-агент / многоходовая переписка | Одноразовый extract→review проще строить и ограждать |
| Агент запускает наряд-допуск / двигает статусы / что-либо согласует | Чувствительно к безопасности и полномочиям |
| Vector DB / embeddings | Избыточно для одного участка; неревьюабельный путь сопоставления |
| Совместное редактирование предпросмотра в реальном времени | Сложность конкурентности ради редкого случая |
