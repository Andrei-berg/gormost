<objective>
Freeze the cross-phase resolver contract (D-07) and prove it end-to-end with the thinnest
possible vertical slice: a Russian phrase enters `preprocess()`, an index built by
`buildKbIndex()` is consulted, and `resolveEntity()` returns a real catalog id via the exact-alias
path — or an honest `unresolved`. Every module in the D-08 file layout exists with its final
signature after this plan, so later plans only fill in behaviour, never reshape the architecture.

Purpose: Phase 9 (Excel ingest) and Phase 11 (dictation review) consume `resolveEntity` verbatim.
Getting the contract wrong is a one-way door — this plan lands it first, on the executor's best
early-context tokens, before migrations or admin UI expand around it.

Output: `src/lib/kb/` with 9 source modules + the fixture file + 2 test files, `npm run test` green.
</objective>

<assumption_delta_decision>
Primary noun: `lemmatize` — the token-transform module (D-12).
Decision: **no-change**.
Rationale: the assumption-delta detector fired on weak generalization cues ("also", "fallback")
around D-12's swappable lemmatizer. This is an already-decided module boundary
(`(token: string) => string`) with the vendored Porter-RU stemmer as the guaranteed
implementation and a mandatory fixture gate (D-12a) any replacement must pass. It is not a
singular→plural identity shift in the data model: there is exactly one `lemmatize` in the
pipeline, and swapping its internals cannot change the primary key or identity of any entity.
The module boundary + fixture gate already isolate the swap; no promote and no add-alongside is
warranted. What would force a revisit: a lemmatizer that needs async initialization, which would
change `preprocess`/`resolveEntity` from sync to async and break the frozen D-07 contract — that
candidate must be rejected by the spike (Plan 08-02), not accommodated.
</assumption_delta_decision>

| Boundary | Description |
|----------|-------------|
| Russian free text -> resolver | Untrusted phrase (later: pasted dictation, Excel cell) crosses into `preprocess`/`resolveEntity` |
