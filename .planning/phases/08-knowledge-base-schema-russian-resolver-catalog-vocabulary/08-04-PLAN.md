<objective>
Add the KB persistence layer: a `src/lib/api/knowledge.ts` domain module for `entity_aliases` CRUD
plus the ADMIN-gated work-type attribute writer, wired through the three-edit house pattern
(barrel export, `ROLE_RESTRICTED`, hand-kept `api-client.ts` wrappers), and the shared TypeScript
types the admin tabs and the resolver both consume.

Purpose: `/api/db` auto-exposes every barrel export by name. Adding the module and forgetting the
gate would put alias and work-type mutations behind a shared demo PIN — the single highest-severity
threat in this phase. The gate ships in the same plan as the module and is enforced by a test.

Output: 6 API functions, 6 client wrappers, 4 `ROLE_RESTRICTED` entries, extended shared types, and
a gating guard test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> `/api/db` | Any authenticated session (shared demo PIN `1234`) can POST `{fn, args}`; the barrel makes every export reachable by name |
| `/api/db` -> Supabase | Server-side anon-key client writes `entity_aliases` and `work_types` |
| Caller-supplied `attrs` object -> `work_types` UPDATE | An unfiltered spread would let a caller write columns outside the four KB attributes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-12 | Elevation of privilege | KB mutations auto-exposed by the `/api/db` dispatcher | high | mitigate | Four `ROLE_RESTRICTED` entries mapped to the ADMIN role only (D-20); `knowledge.gating.test.ts` derives mutation names from the source file and fails the build if any is ungated (ASVS V4/V13) |
| T-08-13 | Tampering | Unfiltered `attrs` spread into the `work_types` UPDATE | high | mitigate | `updateWorkTypeAttributes` whitelists exactly `service_id`, `unit`, `typical_period`, `typical_crew` before calling Supabase; the parameter type rejects other keys at compile time |
| T-08-14 | Tampering | Caller-supplied `surface_norm` diverging from the resolver's index key | medium | mitigate | `createEntityAlias`/`updateEntityAlias` derive `surface_norm` from `preprocess(surface_raw).normalized`, never from the caller |
| T-08-15 | Repudiation | Alias provenance lost | low | mitigate | `source` and `created_by` are part of the D-14 DDL and are written by the create path; `surface_raw` is stored verbatim for audit |
| T-08-16 | Information disclosure | Supabase error text surfaced to the client | low | accept | House pattern: Russian message plus the Supabase message, mapped to `{ error }` by the route; no secrets are present in these messages (ASVS V7) |
| T-08-17 | Tampering (stored XSS) | `surface_raw` rendered in the admin list | medium | mitigate | Stored verbatim for display/audit and rendered as React text only; the raw-HTML prohibition is enforced in Plan 08-09 where the list is built |
</threat_model>
