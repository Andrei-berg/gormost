<objective>
Rebuild `/admin` → «Виды работ» as a dedicated editor (D-17) so an ADMIN can teach the agent which
service owns each work type and what its unit, typical period and typical crew are — the attributes
that make a work type usable by the resolver and that prefill Phase 11 draft rows.

Purpose: KB-02's success criterion is a round trip through the UI: set the four attributes, reload,
they are still there. Nothing else in this phase makes `work_types` rows enter `KbIndex`, because
`buildKbIndex` only loads rows with a non-null `service_id`.

Output: `WorkTypeAttributesTab.tsx` wired into the admin tab router, with the D-18 affordances that
keep an ADMIN from getting stuck in a long catalog.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser form input -> `updateWorkTypeAttributes` | ADMIN-entered values reach a database UPDATE through `/api/db` |
| Shared demo PIN session -> ADMIN-only mutation | The deployment is public with a shared PIN, so role gating is the only barrier |
| Work-type attributes -> Phase 11 draft prefill | Values set here become the defaults on generated plan rows |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-12 | Elevation of privilege | `updateWorkTypeAttributes` reachable by a non-ADMIN session | high | mitigate | `ROLE_RESTRICTED` maps it to the ADMIN role only (Plan 08-04, D-20); `knowledge.gating.test.ts` fails the build if the entry is removed; the page itself is wrapped in `AuthGuard roles={['ADMIN']}` |
| T-08-32 | Tampering | Negative or fractional crew counters written to `typical_crew` | medium | mitigate | Change handlers clamp at zero and coerce to integer before state is set; the UAT explicitly attempts both |
| T-08-33 | Tampering | `typical_crew` keys drifting to the `required_*` spelling | high | mitigate | Keys are locked in `TypicalCrew` (Plan 08-01/08-04) and the acceptance criterion greps the component for the forbidden spelling; Phase 11 EXT-05 prefill depends on it (RESEARCH Pitfall 5) |
| T-08-34 | Input validation | An out-of-set `typical_period` value | medium | mitigate | The segmented toggle offers exactly three options derived from the `SHIFT_HOURS` эталон; the database CHECK from migration 053 is the backstop (ASVS V5) |
| T-08-35 | Denial of service | Bulk action looping many updates and hanging the tab | low | mitigate | One bulk action only, with the button disabled and progress shown while it runs, followed by a single `reload()`; richer bulk operations are deferred to v3.x |
| T-08-17 | Tampering (stored XSS) | Free-text `unit` and work name rendered in the table | medium | mitigate | Rendered as React text only; no raw HTML anywhere in the component |
</threat_model>
