<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anon-key server client -> Postgres | Every read and write from `/api/db` reaches tables as the anon role; RLS is the only gate |
| Migration file -> Supabase SQL Editor | A human pastes the file; the editor's client-side validator is part of the trust path |
| Polymorphic `canonical_id` -> four different tables | No foreign key can enforce the target |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-22 | Denial of service (self-inflicted) | `entity_aliases` with RLS enabled and no policy | high | mitigate | `anon_all_entity_aliases` created in migration 054 in the same file as the table, mirroring migration 050; the acceptance criterion greps for it and for any table-creating migration lacking a policy (SC#1, CLAUDE.md RLS invariant) |
| T-08-23 | Denial of service | Migration rejected by the Supabase SQL Editor validator | medium | mitigate | Unique expression index over `coalesce(scope_object_id::text, '')` is the primary mechanism; the native `NULLS NOT DISTINCT` form is not used (RESEARCH Pitfall 1) |
| T-08-24 | Tampering | ALTER written against an assumed `work_types` shape | high | mitigate | Task 1 dumps the live schema via `list_tables` and `get_advisors`; Task 2 is a blocking decision checkpoint showing the delta before the one-way DDL is written (RESEARCH Pitfall 7) |
| T-08-05 | Elevation of privilege | Permissive `anon_all` policy on `entity_aliases` | medium | accept | House invariant for every table in this project; access control is enforced above, at `/api/db` via `ROLE_RESTRICTED` (Plan 08-04) and the `gormost_token` session check. Aliases hold no personal data (ASVS V4, RESEARCH Assumption A7) |
| T-08-25 | Integrity | Dangling polymorphic `canonical_id` after an entity is deleted | medium | mitigate | `scope_object_id` carries ON DELETE CASCADE; `canonical_id` is intentionally foreign-key-less and `buildKbIndex` skips unresolvable ids (Plan 08-05); the rule is documented in the table comment and `docs/catalog-map.md` |
| T-08-26 | Input validation | Invalid `canonical_type`, `source` or `typical_period` values | medium | mitigate | CHECK constraints in the DDL are the last line of defence behind the TypeScript types added in Plan 08-04 (ASVS V5) |
