## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Unknown Russian phrase -> resolver | The phrase is untrusted and may resemble a real catalog row without being one |
| Resolver score -> downstream chip / write path | Phase 11 renders the chip from `score` and writes the returned id into `daily_plan_items.object_id` |
| Alias table content -> resolution outcome | An ADMIN-entered alias directly steers what a phrase resolves to |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Tampering (data integrity) | `resolveEntity` fuzzy layer coercing an unknown phrase to a real id | high | mitigate | `low` calibrated against at least 3 unknown-phrase fixtures that must return 'unresolved'; a whole-fixture invariant loop asserts every 'resolved' id is a member of the loaded id set; deleting a failing unknown case to go green is prohibited by the task action (RESEARCH Pitfall 3) |
| T-08-18 | Tampering | Alias `weight` used to force a low-confidence fuzzy guess to 'resolved' | high | mitigate | D-15 implemented literally: `weight` participates only in ordering and tiebreaks; a test asserts a high-weight alias does not lift a below-`low` score to 'resolved' |
| T-08-02 | Tampering (dangling reference) | Polymorphic `canonical_id` with no foreign key | medium | mitigate | `buildKbIndex` skips aliases whose `canonical_id` is absent from the loaded rows of that type; `index.test.ts` asserts the skip |
| T-08-19 | Repudiation / misinterpretation | `score` read downstream as a model probability | medium | mitigate | Header comment in `resolve.ts` states `score` is resolution confidence from match strength with the monotonic ordering alias > exact > lemma > trigram; repeated in `docs/catalog-map.md` (Plan 08-06) (RESEARCH Pitfall 4) |
| T-08-20 | Denial of service | Fuzzy scan cost growing with catalog size | low | accept | In-memory scan over a single-участок catalog; `pg_trgm` and SQL-side fuzzy are explicitly deferred (D-06, CONTEXT § Deferred) and the contract does not change if introduced later |
| T-08-21 | Tampering | A colliding alias silently resolving to one arbitrary canonical | medium | mitigate | `collisions.ts` predicate plus a test asserting a colliding surface returns 'ambiguous' rather than a pick (D-13) |
</threat_model>
